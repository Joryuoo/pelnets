### Explanation
Based on the text and Figure 3 detailing the operations for ensuring authentication and confidentiality of the email body:

- **Blank A (Session key):** The description states, "In PGP, the symmetric key is used only once, and a new random 128-bit session key is generated for each message." Figure 3 shows generating `A` and then encrypting the message `X` using `A`. Therefore, `A` is the **Session key** (h).
- **Blank B (Receiver's public key):** The text mentions, "For protection, the session key is encrypted by using the receiver’s public key." Figure 3 shows encrypting `A` (the session key) using `B` before appending it to the message. Thus, `B` is the **Receiver's public key** (e).
- **Blank C (Receiver's private key):** At the receiver site, to retrieve the session key, it must be decrypted using the receiver's own private key (since it was encrypted with the receiver's public key). Figure 3 shows decrypting `A` using `C`. Therefore, `C` is the **Receiver's private key** (d).

**Incorrect Choices:**
- **a) 64-bit cipher key:** The algorithm uses 64-bit cipher feedback mode, but the key itself is a 128-bit session key.
- **c) Hash key:** A hash is generated from the message for the digital signature, but it is not used to encrypt the message body or the session key.
- **f) Sender's private key / g) Sender's public key:** The sender's keys are used for the digital signature (authentication), not for the symmetric session key's encryption (confidentiality). Encrypting the session key with the sender's private key would allow anyone with the sender's public key to decrypt it, failing to provide confidentiality.
