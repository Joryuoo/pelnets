The given functional dependencies are:
1. `a -> h`
2. `b -> c`
3. `e -> f`

To convert to **Second Normal Form (2NF)**, we must remove partial dependencies (non-key attributes that depend on only part of the primary key):
* Attribute `h` depends only on `a`, creating a new relation: `R1(a, h)`
* Attribute `c` depends only on `b`, creating a new relation: `R2(b, c)`
* The remaining non-key attributes that fully depend on `{a, b}` are `d, e, f, g`. So, we have: `R3(a, b, d, e, f, g)`

To convert to **Third Normal Form (3NF)**, we must remove transitive dependencies from `R3` (non-key attributes depending on other non-key attributes):
* In `R3`, attribute `f` depends on `e`, and `e` is not a candidate key. This forms a new relation: `R4(e, f)`
* Removing `f` leaves the main relation: `R5(a, b, d, e, g)`

The final set of normalized tables is `{a, h}`, `{b, c}`, `{e, f}`, and `{a, b, d, e, g}`. This precisely matches Choice C.
