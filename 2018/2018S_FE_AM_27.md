# 2018S_FE_AM_27
![[2018S_FE_AM_Q27_p1.png]]

a) Delivery_date → Component_ID
b) Delivery_destination → Component_ID
c) Department_ID → Component_ID
d) Department_name → Delivery_destination
?
b) Delivery_destination → Component_ID
### Explanation
In a relational database, a functional dependency `X → Y` means that if two records have the same value for `X`, they must also have the exact same value for `Y`. Let's test the given options against the table:

- **Delivery_date → Component_ID:** The date "2016-08-30" is associated with both Component_ID 2346 and 1342. (False)
- **Department_ID → Component_ID:** The ID "500" is associated with both Component_ID 2346 and 1342. (False)
- **Department_name → Delivery_destination:** The "Research and development department" is associated with Delivery_destinations "Boston factory" and "New York office". (False)
- **Delivery_destination → Component_ID:** 
  - "Chicago office" always has Component_ID 1342.
  - "Boston factory" always has Component_ID 2346.
  - "New York office" always has Component_ID 1342.
  Since each unique Delivery_destination is associated with only one unique Component_ID, this dependency holds true.
