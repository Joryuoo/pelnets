### Explanation
**Blank F:** The key must now be between `-25` and `25` (inclusive). We must reject the input (continue looping) if the key falls outside this range. A concise way to check if an integer $k$ is outside $[-25, 25]$ is whether $k \neq k \pmod{26}$. Wait, let's analyze the options: `key != (key % 26)`. If `key` is `26`, `26 % 26` is `0`, which is not `26` (so it loops). If `key` is `25`, `25 % 26` is `25`, which equals `key` (so it breaks the loop). Thus, the expression `key != (key % 26)` accurately checks if the key is out of bounds. The answer is `b`.

**Blank G:** If the user enters a negative key (e.g., `-3`), we can convert it into an equivalent positive shift to reuse the existing modular arithmetic in the encryption function without causing negative modulo results. A shift of `-3` in a 26-letter alphabet is identical to a positive shift of `23` (`-3 + 26 = 23`). Therefore, if `key < 0`, we simply add 26 to it: `key += 26`. The answer is `f`.
