### Explanation

**a is correct:** PGP relies on a decentralized "Web of Trust" where users manually exchange and sign each other's public keys rather than relying on a centralized Certificate Authority. Prior to a robust web of trust being established, there is no central authority to verify identities, making it easier for malicious users to generate key pairs with fake identities.

**b is incorrect:** In hybrid cryptography (like PGP), the message payload is only encrypted once using a symmetric transaction key. Only this small transaction key needs to be encrypted $n$ times (once for each recipient's public key), making it highly efficient for multiple recipients.

**c is incorrect:** Hybrid cryptography is used precisely because symmetric-key encryption is much faster and more efficient for large data than pure public-key cryptography. Therefore, encrypting large attachments is significantly faster than using pure public key cryptography.

**d is incorrect:** The transaction key is a one-time session key created dynamically (using a random seed). It is strictly used only once for a particular message and cannot be reused for subsequent messages.

**e is incorrect:** Data compression actually reduces the redundancy and repetitive patterns commonly found in plaintext. By eliminating these patterns before encryption, it makes the message more resilient (not more vulnerable) against certain crypto-analytic attacks.
