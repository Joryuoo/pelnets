**Explanation:**
Based on the values in Figures 3a and 3b:
Currently available resources: `availR` = (0, 1, 1).

We must check the required resources (`maxP - allocP`) for each process:
- **P0 needs:** (4-2, 1-1, 1-0) = (2, 0, 1). Cannot execute because it needs 2 of R0, but 0 are available.
- **P1 needs:** (1-1, 3-1, 1-0) = (0, 2, 1). Cannot execute because it needs 2 of R1, but 1 is available.
- **P2 needs:** (1-1, 1-0, 2-1) = (0, 1, 1). Can execute because it requires exactly what is available.

Since only P2 can execute, P2 runs to completion. Once P2 finishes, its allocated resources (1, 0, 1) are returned to `availR`.
New `availR` = (0+1, 1+0, 1+1) = (1, 1, 2).

Now we evaluate the remaining processes (P0 and P1) with the new `availR`:
- **P0 needs:** (2, 0, 1). Cannot execute because it needs 2 of R0, but only 1 is available.
- **P1 needs:** (0, 2, 1). Cannot execute because it needs 2 of R1, but only 1 is available.

Neither P0 nor P1 can execute, meaning the system has entered a deadlock state.
Therefore, P2 is executed and finished, but P0 and P1 are in a deadlock state. (Answer: **e**)
