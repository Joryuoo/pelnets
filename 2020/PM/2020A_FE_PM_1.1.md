### Explanation

**Blank A:** Bob's private key (c)
The transaction key was originally encrypted using the recipient's (Bob's) public key so that only the recipient can decrypt it. Therefore, to decrypt the transaction key upon receiving the message, Bob must use his own private key.

**Blank B:** RSA (b)
As specified in Table 1, the public-key algorithm used in this process is RSA. This algorithm is used to decrypt the transaction key.

**Blank C:** SHA-1 (c)
To ensure the integrity of the message, Bob must independently create a message digest from the compressed message. According to Table 1, the hash algorithm used for this purpose is SHA-1.

**Blank D:** Alice's public key (b)
The original message digest was signed (encrypted) using the sender's (Alice's) private key to ensure authenticity. To verify the signature, Bob must decrypt it using Alice's public key.

**Blank E:** Alice's private key (a)
In a Web of Trust, users vouch for others by signing their public keys. If Alice is introducing Mark to Bob, she acts as the introducer by signing Mark's public key with her own private key, thus validating Mark's identity to Bob.
