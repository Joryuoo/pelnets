# 2023S_FE-A_59

In the system design phase, when an audit is performed on the control to reduce the risk of user requirements not being met, which of the following is a point to be checked?

a) Whether programming is performed in accordance with the specified conventions and standards
b) Whether the program specifications are created based on the system design documents
c) Whether the test plan is created based on the system test requirements, and the manager’s approval of the system operations department is obtained
d) Whether the user department participates in the review of the system design documents
?
d) Whether the user department participates in the review of the system design documents

### Explanation

During the **system design phase**, the primary risk regarding "user requirements not being met" is that the IT design team misinterprets or ignores what the users originally requested. To mitigate this risk, the users (who defined the requirements) must validate that the system design accurately reflects their needs. 

Therefore, a system audit focusing on this specific risk must check if the **user department actively participates in reviewing and approving the system design documents**.

| Option | Phase / Purpose | Why it is incorrect |
| :--- | :--- | :--- |
| **a** | **Programming phase** | Checking coding standards ensures code quality, but does not confirm if the original user requirements were understood and met. |
| **b** | **Detailed design phase** | Ensuring program specs match system design verifies internal IT consistency, but does not verify if the system design itself meets the *user's* requirements. |
| **c** | **Testing phase** | Approving a test plan ensures testing is organized, but does not evaluate the system design against user requirements. |
| **d** | **System design phase** | Involving the user department directly guarantees that the design is checked against the actual user requirements. |
