### Explanation
**Blank A:**
In the **Linked allocation method**, each block contains a pointer to the next block. To access a specific part of the file (direct-access / random access), the operating system must read the blocks sequentially from the beginning, following the pointers one by one until it reaches the desired block. This makes it highly inefficient for direct access. Thus, the correct answer is `b)`.

**Blank B:**
In the **Indexed allocation method**, each file requires at least one separate index block to store its block pointers, regardless of how small the file is. For a system with a large number of very small files (e.g., 1-block files), every file will require an extra entire block just for the index, leading to significant wasted space compared to linked allocation. Thus, the correct answer is `c)`.

**Blank C (C1 and C2):**
We are asked to calculate the number of blocks to store a $40\text{ kB}$ data file. 
Given: Block size = $4\text{ kB}$ ($4096\text{ bytes}$), Index value/Pointer = $4\text{ bytes}$.
- **Linked allocation (C1):** 
  Each block holds data and a 4-byte next-block pointer.
  Capacity for data per block = $4096 - 4 = 4092\text{ bytes}$.
  Total data size = $40 \times 1024 = 40960\text{ bytes}$.
  Number of blocks needed = $\lceil 40960 / 4092 \rceil = \lceil 10.009 \rceil = 11\text{ blocks}$.
- **Indexed allocation (C2):**
  Data is stored purely in data blocks.
  Capacity for data per block = $4096\text{ bytes}$.
  Data blocks needed = $\lceil 40960 / 4096 \rceil = 10\text{ blocks}$.
  The 10 pointers will take $10 \times 4 = 40\text{ bytes}$, which fits well within a single index block.
  Total blocks = $10\text{ (data blocks)} + 1\text{ (index block)} = 11\text{ blocks}$.
Therefore, C1 = 11 and C2 = 11, which matches option `d)`.
