# 2023S_FE-A_55

Which of the following is an appropriate explanation of the Function Point method for creating an estimate for software development?

a) It is a method for estimating the overall workload, where the development work is broken down into units of work items. The cumulative total of the workload for each item is then calculated based on a predefined standard value for the workload that is applied to each individual work item.
b) It is a method for estimating the person-hours and development duration, on the assumption that the development scale is known. It can be applied to all fields, not just to the business field.
c) It is a method for estimating the scale and person-hours of development based on some past experience of similar software, where similarities and differences of software are analyzed while past data is used for the similarities and past experience for the differences.
d) It is a method for estimating the scale of software, where the functions of the software are quantitatively measured using elements such as the number of I/O data items and the number of files, and an adjustment is performed based on the complexity.
?
d) It is a method for estimating the scale of software, where the functions of the software are quantitatively measured using elements such as the number of I/O data items and the number of files, and an adjustment is performed based on the complexity.

### Explanation

The **Function Point (FP) method** is used to estimate the size and complexity of a software system based on the functionality it provides to the user, independent of the technology or programming language used to implement it.

It works by measuring functional parameters (such as external inputs, external outputs, external inquiries, internal logical files, and external interface files) and multiplying them by complexity factors (weights) to determine the overall software scale.

| Option | Estimation Method | Description |
| :--- | :--- | :--- |
| **a** | **Work Breakdown Structure (WBS) / Bottom-up Estimating** | The workload is divided into smaller work items, and their individual estimates are aggregated to determine the total workload. |
| **b** | **COCOMO (Constructive Cost Model)** | An algorithmic software cost estimation model that uses mathematical formulas to predict person-hours and duration once the initial scale (like lines of code) is known. |
| **c** | **Analogous / Dot-counting Estimating** | Estimation is based on past experience and historical data from similar software projects, adjusting for known differences. |
| **d** | **Function Point (FP) Method** | Software scale is estimated by counting functional elements (I/O data, files) and adjusting them based on complexity. |
