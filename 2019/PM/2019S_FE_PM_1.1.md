### Explanation

**Hybrid Encryption Schema:**
Hybrid encryption combines the efficiency of symmetric-key encryption with the convenience of public-key encryption. 
- **Symmetric-key encryption** is used for encrypting the data (plain message) because it is faster for bulk data. The key used here is called a session key (`sk`).
- **Public-key encryption** is used for securely transmitting the session key. The sender encrypts the session key using the receiver's public key, so only the receiver can decrypt it with their private key.

**Analyzing the Sender's side:**
1. A session key `sk` is generated for the encryption.
2. `c1 <- A(m, sk)`: The plain message `m` is encrypted using the session key `sk`. As per the description, data encapsulation uses the symmetric-key encryption function, so **A is SENC (d)**.
3. `c2 <- B(sk, C)`: The session key `sk` is encrypted to be transmitted securely to the receiver. This uses the public-key encryption function, so **B is PENC (b)**. To ensure only the intended receiver can decrypt the session key, it must be encrypted using the receiver's public key, so **C is rpk (a)**.

**Analyzing the Receiver's side:**
1. The receiver receives the encrypted message `c1` and the encrypted session key `c2`.
2. `E <- F(c2, D)`: The receiver decrypts `c2` to recover the session key. The function used must be the inverse of PENC, which is the public-key decryption function, so **F is PDEC (a)**. The key used for this decryption is the receiver's own private key, so **D is rsk (b)**. The output of this decryption (`E`) is the recovered session key, so **E is sk (c)**.
3. `m <- SDEC(c1, E)`: Finally, the original plain message `m` is recovered by decrypting `c1` using the symmetric-key decryption function (`SDEC`) and the recovered session key `E` (`sk`).
