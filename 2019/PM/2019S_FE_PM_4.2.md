# 2019S_FE_PM_4.2

![[2019S_FE_PM_Q4_SQ2_p1.png]]

?
d, a, a

### Explanation
**Blank D:**
The checker generates syndrome-bits `110`, meaning `s2=1`, `s1=1`, `s0=0`.
To identify the error bit, we look at the equations for `s2, s1, s0`. Since `s0=0`, the erroneous bit must **not** be part of the `s0` equation. 
The variables in the `s0` equation are `b2, b1, b0, q0`. So none of these have an error.
Since `s2=1` and `s1=1`, the error must be in a variable that is present in **both** the `s2` and `s1` equations.
* `s2` includes `b3, b1, b0, q2`
* `s1` includes `b3, b2, b1, q1`

The intersection of variables in `s2` and `s1` is `{b3, b1}`. Since `b1` is ruled out by `s0`, the only remaining variable is `b3`.
Thus, there is an error in bit `b3`.
Answer is **d) b3**.

**Blank E:**
The sent code-bits are `1101000`. The received code-bits are `0001000`.
Here, `b3=0, b2=0, b1=0, b0=1, q2=0, q1=0, q0=0`.
The receiver generates the syndrome-bits:
* `s2 = b3  b1  b0  q2` = 0  0  1  0 = 1
* `s1 = b3  b2  b1  q1` = 0  0  0  0 = 0
* `s0 = b2  b1  b0  q0` = 0  0  1  0 = 1

The syndrome-bits are `101`. To find which bit the checker assumes is in error, we need a bit present in `s2` and `s0`, but not in `s1`.
* Variables in `s2`: `b3, b1, b0, q2`
* Variables in `s0`: `b2, b1, b0, q0`
* Intersection: `{b1, b0}`
* Variables in `s1`: `b3, b2, b1, q1`. We exclude `b1`.
This leaves `b0`. The checker realizes there is an error in bit `b0`.
Answer is **a) b0**.

**Blank F:**
Because the checker believes bit `b0` is in error, it flips the received `b0` from `1` to `0` to correct it.
The received code-bits `0001000` are "corrected" to `0000000`.
The receiver then extracts the data-bits `b3, b2, b1, b0`, which are `0000`.
Answer is **a) 0000**.
