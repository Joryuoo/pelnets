# 2019A_FE_AM_29
![[2019A_FE_AM_Q29_p1.png]]

a) SELECT ProductNumber FROM Product WHERE EXISTS (SELECT ProductNumber FROM Product)
b) SELECT ProductNumber FROM Inventory WHERE NOT EXISTS (SELECT ProductNumber FROM Product)
c) SELECT ProductNumber FROM Product WHERE EXISTS (SELECT ProductNumber FROM Inventory WHERE Product.ProductNumber = Inventory.ProductNumber)
d) SELECT ProductNumber FROM Product WHERE NOT EXISTS (SELECT ProductNumber FROM Inventory WHERE Product.ProductNumber = Inventory.ProductNumber)
?
d) SELECT ProductNumber FROM Product WHERE NOT EXISTS (SELECT ProductNumber FROM Inventory WHERE Product.ProductNumber = Inventory.ProductNumber)
### Explanation
The original SQL statement uses the `NOT IN` clause:
```sql
SELECT ProductNumber FROM Product 
    WHERE ProductNumber NOT IN (SELECT ProductNumber FROM Inventory)
```
This query selects `ProductNumber` from the `Product` table that do not exist in the `Inventory` table. 

This is logically equivalent to using a correlated subquery with `NOT EXISTS`. Option d) effectively checks for each row in the `Product` table whether there is no matching row in the `Inventory` table with the same `ProductNumber`:
```sql
SELECT ProductNumber FROM Product 
   WHERE NOT EXISTS (
       SELECT ProductNumber FROM Inventory 
       WHERE Product.ProductNumber = Inventory.ProductNumber
   )
```
Therefore, `NOT EXISTS` combined with a correlation on `ProductNumber` produces the exact same result. Option c) uses `EXISTS`, which would return products that *are* in the inventory.
