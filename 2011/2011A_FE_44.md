### Explanation
In public key cryptography, encryption for **confidentiality** requires the sender to encrypt the message using the recipient's public key. 

Since Mr. A wants to send a confidential message to Mr. B:
1. Mr. A encrypts the message with **Mr. B's public key** (Key K).
2. The encrypted message is sent over the network.
3. Mr. B receives the message and decrypts it using his own **private key**.

Because only Mr. B possesses his private key, only he can decrypt the message, ensuring confidentiality.

**Why other options are wrong:**
- **a)**: Public key cryptography uses asymmetric keys (public/private pairs), not a common shared private key (symmetric key).
- **b)**: Encrypting with Mr. A's private key is used for digital signatures (authentication), not confidentiality, as anyone with Mr. A's public key could decrypt it.
- **c)**: Encrypting with Mr. A's public key would mean only Mr. A could decrypt it, making it useless to send to Mr. B.
