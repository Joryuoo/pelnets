# 2011A_FE_8

![[2011A_FE_AM_Q8_full.png]]
?
c) O(m + n)

### Explanation
This question asks for the computational complexity of the standard merge algorithm used to combine two sorted arrays into a single sorted array.
To merge an array of size `m` and an array of size `n`, the algorithm uses pointers for both arrays, comparing elements and inserting the smaller one into the new array. In the worst-case scenario, every element from both arrays must be compared and moved exactly once.
Since there are `m + n` total elements, the number of operations is directly proportional to the total size of the output array.
Thus, the time complexity is `O(m + n)`.
- `O(m)` or `O(n)` are incorrect because both arrays must be fully traversed.
- `O(m * n)` is incorrect; this would apply to a nested loop approach, not a linear two-pointer merge.
