### Explanation

Packet filtering by firewalls operates at the network and transport layers (checking IP addresses and port numbers) to allow or deny traffic based on defined rules.

- **a) Attacks by unauthorized access from the Internet to the corporate LAN:** Packet filtering can block unauthorized access attempts by denying traffic from the Internet directly to the corporate LAN, as seen in the default "Deny" rules for unexpected traffic.
- **b) Leakage of files from the company via e-mail:** Packet filtering cannot inspect the contents (payload) of emails to detect file leakage. This requires an application-layer gateway or data loss prevention (DLP) system.
- **c) SQL injection attacks on the Web site:** Packet filtering only sees that traffic is destined for port 80 (HTTP) and allows it. It cannot inspect the HTTP payload for malicious SQL queries. This requires a Web Application Firewall (WAF).
- **d) Wiretapping and falsification of data exchanged with the Web site:** Packet filtering cannot encrypt data. Protecting against wiretapping requires encryption protocols like HTTPS (SSL/TLS).
