# 2024A_FE-A_29

Which of the following description is an appropriate use of asymmetric encryption to ensure the confidentiality of a message that a sender is going to send to a receiver?

a) The message is encrypted using a pre-shared secret key.
b) The message is encrypted using a private key of the sender.
c) The message is encrypted using a public key of the receiver.
d) The message is encrypted using a public key of the sender.
?
c) The message is encrypted using a public key of the receiver.

### Explanation

**Asymmetric encryption** (also known as Public-Key Cryptography) uses mathematically linked key pairs: a **Public Key** (which can be freely distributed) and a **Private Key** (which must be kept secret by the owner).

Depending on the goal, the keys are used differently:
1.  **To ensure Confidentiality:** The sender encrypts the message using the **receiver's Public Key**. Only the receiver holds the matching Private Key required to decrypt it, ensuring no one else can read the message.
2.  **To ensure Authentication (Digital Signature):** The sender encrypts (signs) a hash of the message using the **sender's Private Key**. Anyone can use the sender's Public Key to verify it, proving the sender truly sent it.

#### Analyzing the Options

| Option | Cryptographic Concept | Explanation |
| :--- | :--- | :--- |
| **a** | Symmetric Encryption | A pre-shared secret key implies symmetric cryptography (like AES), not asymmetric. |
| **b** | Digital Signature | Encrypting with the sender's private key provides authentication/non-repudiation, not confidentiality (anyone with the public key can read it). |
| **c** | **Confidentiality (Correct)** | Encrypting with the receiver's public key ensures that *only* the receiver (using their private key) can decrypt and read the message. |
| **d** | Invalid Operation | Encrypting with the sender's public key would mean only the sender could decrypt it, which makes no sense for sending a message to a receiver. |
