- **Blank A**: The problem specifies that squares with sides of length `n / 4` in each of the four corners should be retained. The variable `unchanged_cells` is used to define the boundaries of these corners. Thus, `unchanged_cells = arr_size / 4;` (Choice d). The other choices define incorrect boundary sizes.
- **Blank B**: The code swaps an element at `[row][col]` with its diametrically opposite element. For a 0-indexed array of size `arr_size`, the diametrically opposite coordinate is found by mirroring across the center: `row` becomes `arr_size - row - 1` and `col` becomes `arr_size - col - 1`. Therefore, the correct reference is `magic_square[arr_size - row - 1][arr_size - col - 1]` (Choice g).
- **Blank C**: This section of `change_cols_diagonally` swaps elements on the right side of the matrix, which are at `[row][arr_size - col - 1]`. The diametrically opposite row is `arr_size - row - 1`. The opposite column is `arr_size - (arr_size - col - 1) - 1`, which mathematically simplifies to `col`. This makes the target `magic_square[arr_size - row - 1][col]` (Choice d).
- **Blank D**: The `tofill` function's purpose is to populate the array with numbers from `1` to `n × n`, sequentially from left to right, top to bottom. This requires standard nested `for` loops starting at index `0` and incrementing up to `arr_size - 1` (Choice a). Options counting down (`>= 0` and `--`) would fill the array in reverse or right-to-left, which violates the described algorithm.
