### Explanation

- **Blank A:** The `add` subprogram inserts a new cell at the head of the singly-linked list (a stack-like LIFO behavior). It first links the new cell to the current head (`Cell[ptr].chain <- ROOT`). To complete the prepend operation, it must update the global head pointer `ROOT` to point to the new cell. Therefore, `ROOT <- ptr` is correct. Incorrect options like `ptr <- ROOT` would overwrite the allocated cell's address.
- **Blank B:** Inside the `delete` subprogram's loop, if the current cell does not match the target `id`, the traversal must advance to the next cell. This is achieved by updating the current index `i` to its next link: `i <- Cell[i].chain`.
- **Blank C:** When deleting a cell that is not the head (`pi ≠ 0`), the `chain` of the previous cell (`pi`) must bypass the deleted cell and point directly to the next cell (`ptr`). Thus, `Cell[pi].chain <- ptr` is correct. Options modifying `Cell[i].chain` are incorrect because `i` is the cell being removed.
- **Blank D:** The `exchange` subprogram swaps the node at `ptr` with its next node `ptr1`. To reorder them, the first node `ptr` must point to the third node `ptr2` (handled by `Cell[ptr].chain <- ptr2`), and the second node `ptr1` must point back to the first node `ptr`. Thus, `Cell[ptr1].chain <- ptr` is correct. Options creating a self-loop (e.g., `Cell[ptr1].chain <- ptr1`) are functionally invalid.
