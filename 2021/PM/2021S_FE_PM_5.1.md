### Explanation
**Blank A:** The `Seat` table represents the individual seats available for a specific scheduled bus run. Since each scheduled run is managed in the `In_use` table, the `Seat` table must contain a foreign key linking to it. Therefore, Blank A is **`In_use_ID` (c)**.

**Blank B:** The system requires assigning a driver to a bus for a specific scheduled run. This assignment happens after the schedule is created, meaning the driver can initially be unassigned (NULL). The appropriate attribute to add to the `In_use` table is a foreign key for the driver. Therefore, Blank B is **`Driver_ID (*)` (b)**.

**Blank C:** In the Level 1 DFD (Figure 3), Process 1.1 "Driver assignment" is responsible for allocating a bus to a route and assigning a driver. To do this, the process must read details about available buses, bus types, and routes. It reads from the data stores representing this static or reference data. Therefore, Blank C is **`Bus, Bus_type, Route` (f)**.

**Blank D:** After Process 1.1 determines the assignment, it must store this scheduled run along with its assigned bus and driver. It writes this transactional data to the `In_use` table. Thus, the data store for Blank D is **`In_use` (d)**.
