# 2025A_FE-A_45

In the system design phase, when an audit is performed on the control to reduce the risk of user requirements not being met, which of the following is a point to be checked?

a) Whether programming is performed in accordance with the specified conventions and standards
b) Whether the program specifications are created on the basis of the system design documents
c) Whether the test plan is created on the basis of the system test requirements, and the manager's approval of the system operations department is obtained
d) Whether the user department participates in the review of the system design documents
?
d) Whether the user department participates in the review of the system design documents

### Explanation
The question asks for an audit checkpoint specifically during the **system design phase** that addresses the **risk of user requirements not being met**.

Let's analyze the options based on the development phase and the risk being mitigated:
- **a) Incorrect.** Checking programming conventions and standards is performed during the **Implementation/Coding phase**, not the system design phase.
- **b) Incorrect.** Verifying program specifications against system design documents is a check for consistency between detailed design and system design, but it does not directly verify if the *user requirements* are being met.
- **c) Incorrect.** Checking the test plan and getting operations approval happens during the **Testing phase** (or test planning phase), focusing on quality assurance rather than directly confirming user requirements during the design phase.
- **d) Correct.** The most direct way to ensure that user requirements are accurately translated into the system design is to have the **user department participate in the review of the system design documents**. An auditor would check if this review process is in place and documented, as it acts as a key control to prevent misinterpretation of requirements.
