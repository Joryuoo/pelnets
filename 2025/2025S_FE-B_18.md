### Explanation

This architecture uses a hybrid encryption approach to securely transfer large files.

**Step 1: Encrypting the File (Blank A)**
- "The file uploaded by the sender is encrypted with the supplied password..."
- The sender encrypts the file with a password, and later, the recipient uses that exact *same* password to decrypt it.
- Since the same key (derived from the password via KDF) is used for both encryption and decryption, this is **Symmetric Key Encryption**. Symmetric encryption is also specifically chosen here because the requirements state these are "very large files," and symmetric algorithms (like AES) are much faster and more efficient for bulk data encryption than asymmetric algorithms.

**Step 2: Sending the Password (Blank B)**
- "The password is encrypted and sent to the recipient as an email message..."
- The sequence diagram shows the server retrieving "Q's public key" and using it to encrypt the password before sending it to Q. Q will then use their own private key to decrypt it.
- Since a public key is used for encryption and a mathematically linked private key is used for decryption, this is **Asymmetric Key Encryption** (Public-Key Cryptography). This securely solves the key distribution problem.
