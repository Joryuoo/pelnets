### Explanation
This question focuses on preventing and mitigating the exposure of hard-coded secrets (like API keys) in source code repositories.

1. **Detecting Secrets Before Committing (A):**
   To prevent developers from accidentally pushing code that contains hard-coded API keys to a repository, the development pipeline should include automated checks. **Integrating automated secret scanning tools** into the pre-commit or CI/CD pipeline will scan the code for known patterns of secrets (like API keys, passwords, or tokens) and block the commit if any are found. This fills blank **A**.

2. **Minimizing Damage if Secrets Evade Detection (B):**
   If a secret somehow bypasses the scanning tools and is published, the risk is that unauthorized users will use it to access external services. To minimize the window of opportunity for an attacker, secrets should have a limited lifespan. **Adding a rule that mandates regular rotation of secrets** ensures that even if a key is compromised, it will eventually expire and be replaced by a new one, limiting the potential damage. This fills blank **B**.

This matches choice **c**.
