### Explanation
Let's analyze the dependencies of the activities:
- **Activity A** and **Activity B** have no preceding activities, meaning they start from the initial node.
- **Activity C** can start only after **Activity B** is completed.
- **Activity D** can start only after **both Activity A and Activity B** are completed.

In an arrow diagram, a dummy activity (represented by a dotted arrow) is used to show a dependency without consuming time or resources.
To show that D depends on A and B, we need the end node of A and the end node of B to converge before D starts. Since C only depends on B, we can't just merge the end nodes of A and B into one. 
Instead, we draw a dummy arrow from the end node of B to the end node of A. Then Activity D starts from the end node of A, which now effectively includes the completion of both A and B. Activity C starts directly from the end node of B.
Looking at the choices, only diagram **b)** correctly shows a dummy activity from the end of B to the end of A, allowing D to start after A and B, while C starts only after B.
