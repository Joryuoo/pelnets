### Explanation

* **Blank A:** A 16-bit virtual address means the system has 2^16 possible addresses. The maximum address is 2^16 - 1 = 65535, which in hexadecimal is FFFFh. So the addresses range from 0 to FFFFh. (Correct answer: d)
* **Blank B:** The high-order 4 bits of the address specify the virtual page number. With 4 bits, you can specify 2^4 = 16 virtual pages. (Correct answer: b)
* **Blank C:** The virtual address is B300h. The highest 4 bits represent the virtual page number, which is Bh (or 11 in decimal). According to the page table snapshot (Figure 2), virtual page 11 maps to physical page 7 (which is 7h). The 12-bit offset is 300h. Therefore, the physical address is formed by concatenating the physical page number (7) with the offset (300h), resulting in 7300h. (Correct answer: h)
* **Blank D (FIFO):** The physical memory can hold 8 virtual pages. Let's trace the page-ins as the pages are accessed:
  * 3 (miss, page-in 3)
  * 1 (miss, page-in 1)
  * 0 (miss, page-in 0)
  * 5 (miss, page-in 5)
  * 4 (miss, page-in 4)
  * 9 (miss, page-in 9)
  * 1 (hit)
  * 2 (miss, page-in 2)
  * 3 (hit)
  * 11 (miss, page-in 11) - Physical memory is now full (8 pages).
  * 6 (miss, page fault occurs).
  
  Under the **First In First Out (FIFO)** algorithm, the page that was brought into memory the earliest will be paged out. Looking at our trace, virtual page **3** was the first page brought in. Therefore, page 3 is paged out. (Correct answer: d)

* **Blank E (LRU):** Under the **Least Recently Used (LRU)** algorithm, the page that hasn't been accessed for the longest time is replaced. Let's look at the access sequence leading up to the page fault:
  Sequence: 3 → 1 → 0 → 5 → 4 → 9 → 1 → 2 → 3 → 11
  
  Let's list the pages in memory from most recently used to least recently used:
  1. 11 (most recent)
  2. 3
  3. 2
  4. 1
  5. 9
  6. 4
  7. 5
  8. 0 (least recent)
  
  Virtual page **0** is the least recently used, so it will be paged out. (Correct answer: a)
