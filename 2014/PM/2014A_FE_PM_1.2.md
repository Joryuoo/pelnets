# 2014A_FE_PM_1.2

b

### Explanation
This subquestion asks us to trace the output values of a 4-bit asynchronous ripple counter made of J-K flip-flops.

Since all `J` and `K` inputs are fixed at `1`, each flip-flop is in **toggle mode**. However, a flip-flop only toggles when it receives a **falling edge** (a change from `1` to `0`) on its Clock input line. 
- `FF1 (W)` receives the main system Clock. It toggles on every clock cycle.
- `FF2 (X)` receives the output of `FF1 (W)` as its Clock. It toggles only when `W` changes from `1` to `0`.
- `FF3 (Y)` receives the output of `FF2 (X)` as its Clock. It toggles only when `X` changes from `1` to `0`.
- `FF4 (Z)` receives the output of `FF3 (Y)` as its Clock. It toggles only when `Y` changes from `1` to `0`.

**Tracing the states:**
- **Initial (cycle c):** `W=1, X=0, Y=0, Z=0`
- **Cycle c+1:**
  - `W` toggles (`1` → `0`). This is a falling edge for `FF2`.
  - `X` toggles (`0` → `1`). This is a rising edge for `FF3`, so `FF3` does not toggle.
  - State: `W=0, X=1, Y=0, Z=0`. (Matches Table 2)
- **Cycle c+2:**
  - `W` toggles (`0` → `1`). This is a rising edge for `FF2`, so `FF2` does not toggle.
  - `X`, `Y`, `Z` stay the same.
  - State: `W=1, X=1, Y=0, Z=0`.
- **Cycle c+3:**
  - `W` toggles (`1` → `0`). This is a falling edge for `FF2`.
  - `X` toggles (`1` → `0`). This is a falling edge for `FF3`.
  - `Y` toggles (`0` → `1`). This is a rising edge for `FF4`, so `FF4` does not toggle.
  - State: `W=0, X=0, Y=1, Z=0`.

Comparing this to the answer choices, `W=0, X=0, Y=1, Z=0` corresponds to choice **b**.

- **a** is incorrect because it represents a later state in the counter sequence.
- **c** is incorrect because it improperly toggles without a falling edge.
- **d** is incorrect because it incorrectly flips multiple states out of turn.
