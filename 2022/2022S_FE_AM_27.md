# 2022S_FE_AM_27

![[2022S_FE_AM_Q27_full.png]]

a)  SELECT FlightCode, City.CityName, City.CityName FROM Flight, City WHERE Flight.OriginCityID = City.CityID AND Flight. DestinationCityID = City.CityID
b)  SELECT FlightCode, OriginCityID, DestinationCityID FROM Flight, City WHERE Flight.OriginCityID = City.CityID AND Flight.DestinationCityID = City.CityID
c)  SELECT FlightCode, c1.CityName, c2.CityName FROM Flight, City c1, City c2 WHERE Flight.OriginCityID = c1.CityID AND Flight.DestinationCityID = c2.CityID
d)  SELECT f1.FlightCode, c1.CityName, c2.CityName FROM Flight f1, Flight f2, City c1, City c2 WHERE f1.OriginCityID = c1.CityID AND f2.DestinationCityID = c2.CityID
?
c) SELECT FlightCode, c1.CityName, c2.CityName FROM Flight, City c1, City c2 WHERE Flight.OriginCityID = c1.CityID AND Flight.DestinationCityID = c2.CityID
### Explanation
The goal is to retrieve the **flight code**, its **origin city name**, and its **destination city name**.

We are given two tables:
- `Flight(FlightCode, OriginCityID, DestinationCityID)`
- `City(CityID, CityName)`

Since the `Flight` table contains two different foreign keys (`OriginCityID` and `DestinationCityID`) that both reference the `City` table, we must join the `City` table **twice** to get both the origin and destination city names.

### Using Table Aliases (Self-Joins)
To query the same table twice independently, we must give it two different **aliases** (e.g., `c1` and `c2`). 

1. **First Join (Origin City):** Join `Flight.OriginCityID` to `c1.CityID`. The origin city name is `c1.CityName`.
2. **Second Join (Destination City):** Join `Flight.DestinationCityID` to `c2.CityID`. The destination city name is `c2.CityName`.

Let's look at the correct SQL structure:
```sql
SELECT FlightCode, c1.CityName, c2.CityName
FROM Flight, City c1, City c2
WHERE Flight.OriginCityID = c1.CityID 
  AND Flight.DestinationCityID = c2.CityID
```

### Analyzing the Options:
- **a)** Uses a single instance of `City` and equates both `OriginCityID` and `DestinationCityID` to the same `CityID`. This would only return flights where the origin and destination are the exact same city.
- **b)** Directly selects `OriginCityID` and `DestinationCityID` instead of retrieving the city *names* from the `City` table.
- **c)** Properly uses two aliases (`c1`, `c2`) for the `City` table to independently retrieve the origin and destination city names. **(Correct)**
- **d)** Incorrectly creates two aliases for the `Flight` table (`f1`, `f2`) but tries to link them to `c1` and `c2` without a coherent relationship, producing an unwanted cross join.

Therefore, the correct answer is **c**.
