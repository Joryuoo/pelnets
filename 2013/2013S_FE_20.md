# 2013S_FE_20
![[2013Apr_FE_AM_Q20_full.png]]

a) When a process based on an I/O request is completed
b) When a task is generated
c) When a task with a higher priority is set to the ready state
d) When an I/O request is issued
?
c) When a task with a higher priority is set to the ready state
### Explanation
In a multitasking OS environment, a task transitions from the **running state** back to the **ready state** when it is preempted by the CPU scheduler. This typically happens for two reasons:
1. The time slice (quantum) allocated to the task expires.
2. A task with a higher priority becomes ready, displacing the currently running task.

- **a)** When an I/O request completes, the task transitions from the **waiting state** to the **ready state**.
- **b)** When a task is first generated (created), it typically enters the **ready state**.
- **d)** When a running task issues an I/O request, it transitions from the **running state** to the **waiting state** because it cannot proceed until the I/O operation finishes.
