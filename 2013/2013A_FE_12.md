# 2013A_FE_12
Which of the following is the appropriate course of actions to be taken by a processor at the occurrence of an interrupt?
(1) Saving of the program register (i.e., program counter)
(2) Transition from the user mode to the privilege mode
(3) Determination of the start address of the interrupt processing routine
(4) Execution of the interrupt processing routine

a) 1 → 3 → 4 → 2
b) 1 → 4 → 2 → 3
c) 2 → 1 → 3 → 4
d) 2 → 3 → 4 → 1
?
c) 2 → 1 → 3 → 4
### Explanation
### Method Explanation

When a processor receives an interrupt during the execution of user programs, it handles the event in the following standard sequence:

1. **(2) Transition from user mode to privilege mode:**
   User mode is restricted for system protection. The processor hardware immediately switches execution mode to privileged (supervisor/kernel) mode so that internal OS interrupt routines and restricted hardware registers can be accessed.

2. **(1) Saving of the program register (program counter):**
   Before the processor changes its execution flow, the current Program Counter (PC) and processor status flags must be saved (typically pushed onto the supervisor stack). This preserves the execution state so the interrupted program can resume cleanly later.

3. **(3) Determination of the start address of the interrupt processing routine:**
   The CPU identifies the interrupt vector number and looks up the Interrupt Vector Table (IVT) in memory to retrieve the starting address of the corresponding Interrupt Service Routine (ISR).

4. **(4) Execution of the interrupt processing routine:**
   The CPU loads the ISR address into the Program Counter and begins executing the interrupt handling instructions.

Therefore, the proper sequence is **(2) → (1) → (3) → (4)** (Choice **c**).

### Why Other Options Are Incorrect
- **a, b:** Transition to privilege mode (2) must occur before the interrupt routine can be executed (4); kernel interrupt handlers cannot execute in user mode.
- **d:** The interrupt routine cannot begin execution (4) before saving the program counter (1); doing so would overwrite or lose the return address, making it impossible to return to the interrupted user program.
