### Explanation

When a digital signature fails verification, it means the **message digest calculated from the received message** does not match the **message digest decrypted from the digital signature**. This mismatch indicates that the message has lost its integrity or authenticity. 

Therefore, the two possible reasons for verification failure are:
* **d) the message was not sent from Arice (Alice):** The sender used a different private key to sign the message. When Bob decrypts the signature using Alice's public key, it yields an incorrect digest.
* **e) third party changed the message:** The message was altered during transmission. When Bob decrypts it and calculates the digest, it will differ from the original digest signed by Alice.

**Why the other choices are incorrect:**
* **a) Arice's public key was stolen & b) Bob's public key was stolen:** Public keys are designed to be public and freely distributed. "Stealing" a public key does not compromise security or cause verification failure.
* **c) collision occurred in function MD:** A hash collision happens when two different messages produce the same message digest. If a collision were successfully exploited, a forged message would have the *same* digest, meaning verification would actually **succeed** (not fail).
* **f) third party monitored the message:** Simply monitoring or intercepting the encrypted message (eavesdropping) does not alter its contents. Therefore, Bob's verification process would still succeed.
