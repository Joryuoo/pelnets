### Explanation

- **Blank A:** In Program 1, `Downloadable` defines the method `void download();` without a body. This defines an interface. Therefore, the keyword is `interface` (f). The `abstract` keyword (a) is used for classes with undefined methods, but `interface` is the standard way to define a purely abstract type with no state in Java, especially when used later with `implements`.
- **Blank B:** Program 3 (`Guest`), Program 4 (`Member`), and Program 5 (`GoldMember`) all inherit from existing classes (e.g., `Guest` inherits from `Customer`). In Java, the keyword for class inheritance is `extends` (b).
- **Blank C and D:** Program 5 defines `GoldMember`. According to the scenario, a Gold Member receives a 10% discount and can download e-books. It extends another customer class and adds downloading capabilities. It `extends` (B) `Member` (C) and `implements` (D) `Downloadable`. The answers are `Member` (d) and `implements` (c). 
- **Blank E:** In Program 8, `cCustomers` is an array that stores instances of `Guest`, `Member`, and `GoldMember`. To hold objects of these different subclasses, the array must be defined as their common abstract superclass, which is `Customer`. Thus, the array creation is `new Customer[CUSTOMERS_COUNT]` (a).
- **Blank F:** In Program 8, `printSalesInfo` calculates the payment by calling `calculatePayment`. Because `calculatePayment` is declared as an abstract method in the `Customer` superclass (Program 2) and implemented in all subclasses, Java's polymorphism will automatically invoke the correct overridden method at runtime. No type casting to specific subclasses is needed. We simply use the returned Customer object: `currentInvoice.getCustomer()` (e).
