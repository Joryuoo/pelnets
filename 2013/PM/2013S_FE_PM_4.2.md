# 2013S_FE_PM_4.2

D=c, E=d

### Explanation

In a digital signature system, the sender uses their own private key to create the signature, and the receiver uses the sender's public key to verify it. This ensures **authenticity** and **non-repudiation**, as only the sender possesses their private key.

*   **Blank D (Creating a digital signature):** The sender encrypts the message digest (hash) using their own private key. Therefore, **D is c) Sender's private key**.
*   **Blank E (Verifying a digital signature):** The receiver decrypts the digital signature to recover the message digest using the sender's public key. Therefore, **E is d) Sender's public key**.

**Why the other choices are incorrect:**
*   **a) Receiver's private key:** The sender does not have access to the receiver's private key to create a signature. Furthermore, if the receiver used it for verification, it would not prove the sender's identity.
*   **b) Receiver's public key:** If the sender used the receiver's public key to create the signature, anyone could forge it (since public keys are publicly available). The receiver's public key is typically used for encrypting confidential messages *to* the receiver, not for digitally signing messages *from* the sender.
