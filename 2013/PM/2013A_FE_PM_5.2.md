### Explanation

According to the requirements, "The number of sweepstakes tickets sent to each customer is to be the same as the number of campaign products the customer purchases during the period." 

In `Table 1`, the `Sweepstakes ticket processing` module is responsible for updating the `Number of sweepstakes tickets` work area. This work area serves as an accumulator for the number of tickets for a specific customer as their records from the work file are processed sequentially. 

Since a single customer might have multiple sales slip records (transactions) for campaign products, the calculation needs to add the `Purchased quantity` from the current work file record to the running total of `Number of sweepstakes tickets`.

Therefore, the correct expression is:
`Number of sweepstakes tickets + Purchased quantity in a record in the work file`

**Why the other choices are incorrect:**
* **a) 1:** This would assign a fixed value of 1, ignoring the actual quantity of products purchased.
* **b) Purchased quantity in a record in the work file:** This would overwrite the running total, meaning only the quantity from the last processed record would be saved.
* **c) and f) [Purchase amount... / 50000]:** This division logic is related to the rule for invitation tickets (one ticket per 50,000 yen spent), not sweepstakes tickets.
* **d) Number of sweepstakes tickets + 1:** This would merely count the number of valid records (transactions), but a single record could have a purchased quantity greater than 1.
