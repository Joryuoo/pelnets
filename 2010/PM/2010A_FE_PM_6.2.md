**Blank E:**
Figure 5 illustrates the final step of creating the heap, where the root node (index 1, value `1`) is shifted down.
1. The root `1` at index 1 is compared with its children: `10` (index 2) and `9` (index 3).
2. The larger child is `10`. So, `1` and `10` are swapped. The array briefly becomes: `10, 1, 9, 7, 7, 5, 2, 2, 4, 6`.
3. Next, the `1` (now at index 2) is compared with its new children: `7` (index 4) and `7` (index 5).
4. Since both children are equal (`7`), the algorithm strictly checks `T[2*j+1] > T[k]` (i.e., is the right child strictly greater than the current max?). Because `7` is not strictly greater than `7`, `k` remains the left child (index 4). The `1` is swapped with the left `7`.
5. The array becomes: `10, 7, 9, 1, 7, 5, 2, 2, 4, 6`. This matches **Option b**, which represents the intermediate array state E. (A subsequent swap of `1` with `4` at index 9 produces the final array shown below E.)

**Blank F:**
The subprogram `make_heap` builds a heap out of an unordered array by calling `shift_down` on all internal nodes, starting from the lowest level up to the root. Since leaf nodes (located at indices `> n/2`) inherently satisfy the heap property as standalone trees, the process starts at the last non-leaf node, which is at index `n / 2`. The loop then iterates backwards down to index 1. For each node `i` in this range, we must establish the heap property for its sub-tree by shifting the node down. Therefore, **Blank F** must be a call to `shift_down(T[ ], n, i)` (Option c). Other choices like `shift_up` would not properly cascade larger values up from the leaves.
