In a relational database design, foreign keys are used to establish relationships between tables.

*   **Blank A:** The `Book` table needs to link each book to its subject. By the principles of normalization, we use the primary key of the referenced table as the foreign key, which is `subject_id`. Using `subject_name` would violate database normalization. This corresponds to choice **h**.
*   **Blank B:** Both `Receipt_detail` and `Sale_invoice_detail` tables represent line items for receipts and sales. Each line item needs to specify *which* book is being received or sold. Therefore, they must include `book_id` as a foreign key linking to the `Book` table. This corresponds to choice **a**.
*   **Blank C:** The `Sale_invoice` table represents a single transaction with a customer. It needs to link the invoice to the customer who made the purchase. Thus, `customer_id` is the appropriate foreign key. This corresponds to choice **b**.
