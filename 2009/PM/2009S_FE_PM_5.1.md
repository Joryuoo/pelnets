The flowchart in Figure 2 prepares the Personnel View by identifying warnings for the assignments made in the calendar and updating the count of unassigned critical requests.

**Blank A:** The first check determines if a scheduled service is late. The system colors the request code "blue" and increments `Cnt_Late` if the service is late. This occurs when the `Visit date` is greater than the `Due date`. Thus, **A** should be `Visit date : Due date` (choice e).
- *Why not other choices?* `Completion date` is only entered once a request is completed, which is not applicable during scheduling.

**Blank B:** The second check identifies if the personnel assigned lacks the necessary expertise, in which case the request code turns "green". This compares the personnel's `Expertise` with the request's `Expertise needed`. Thus, **B** should be `Expertise : Expertise needed` (choice c).

**Blank C:** The first loop in the flowchart calculates `Total_CR` by counting all unassigned critical requests in the `Request file` (due dates within 7 days). The second loop iterates through the requests that have just been assigned in the calendar. If an assigned request is critical (`DueDate <= CurrentDate + 7`), it is no longer unassigned. Therefore, we must decrement `Total_CR` by 1. Thus, **C** is `Total_CR - 1 → Total_CR` (choice d).
- *Why not choice e or f?* Changing the color to "red" is a feature of the Request View, not the checking logic for the Assignment calendar.

**Blank D:** This block executes when the personnel's expertise does not match the required expertise (from Blank B). It simply needs to increment the counter for mismatched expertise. Thus, **D** is `Cnt_Nomatch + 1 → Cnt_Nomatch` (choice a).
