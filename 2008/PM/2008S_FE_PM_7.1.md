**Blank A:** `super.myMethod(superFlag)` (Choice d)
In `Program 1`, `TestSuper` extends `Base` and overrides `myMethod`. The program output shows that when `superFlag` is `true`, the base class method is invoked, printing "Base-class method invoked". To call a method from the superclass that has been overridden in the current class, the `super` keyword must be used. `super.myMethod(superFlag)` correctly invokes `myMethod` in the `Base` class.
- *Choice a* (`this.super...`) is invalid Java syntax.
- *Choice c* (`super()`) is used to call the superclass constructor, which is only valid on the first line inside a constructor.

**Blank B:** `arg instanceof TestEquals` (Choice a)
In `Program 2`, the `equals(Object arg)` method must ensure that the passed object `arg` is of the correct type (`TestEquals`) before attempting to cast it and compare their data fields. The `instanceof` operator evaluates whether an object is an instance of a specific class. If `arg` is not a `TestEquals` object (such as `obj4`, which is a `String`), the condition will evaluate to false, skipping the cast and correctly returning `false`.
- *Choices b and c* incorrectly attempt to use the equality operator `==` to compare an object reference to a class type, which is invalid in Java.

**Blank C:** `((TestEquals)arg).myData` (Choice d)
Once it is guaranteed that `arg` is an instance of `TestEquals`, it must be explicitly cast from `Object` to `TestEquals` in order to access its `myData` member variable. Because the declared type of `arg` is `Object`, the compiler will throw an error if you try to access `myData` directly without casting.
- *Choice b* (`arg.myData`) causes a compilation error because the `Object` class does not have a `myData` field.
- *Choice c* (`arg.getMyData()`) also causes a compilation error for the same reason; `Object` does not define a `getMyData()` method.
