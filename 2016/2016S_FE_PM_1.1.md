### Explanation

**Subquestion 1:**
* **Blank A:** The description emphasizes reviewing source codes and assessing the developed application for security flaws to prevent SQL injection. This process is known as a **vulnerability assessment** (d). Implementing patches is typically for existing commercial software, and TCP/IP scanning or virus checking do not address application-level SQL injection flaws. Thus, **A = d**.
* **Blank B:** The attacker's goal is to create the following query:
  `WHERE UserName='admin' -- ' AND Password=''`
  The original query structure constructed by the Web server is:
  `WHERE UserName='[input_UserName]' AND Password='[input_Password]'`
  To achieve the desired query, the attacker enters nothing `""` in the password field, leaving `[input_Password]` empty. For the user name field, entering `admin' -- ` into `[input_UserName]` results in:
  `WHERE UserName='admin' -- ' AND Password=''`
  This exactly matches the attacker's desired exploit query where the rest of the query is commented out. Thus, **B = c**.
* **Blanks C and D:** The attacker's goal for Case 2 is:
  `WHERE UserName='' AND Password='' OR 'A'='A' LIMIT 1 -- '`
  Using the original query structure, the attacker enters `""` (no input) for the user name. This makes the query:
  `WHERE UserName='' AND Password='[input_Password]'`
  To match the target statement, the attacker must input `' OR 'A'='A' LIMIT 1 -- ` in the password field. Substituting this into `[input_Password]` yields:
  `WHERE UserName='' AND Password='' OR 'A'='A' LIMIT 1 -- '`
  This correctly forms the exploit, making the condition always true (`'A'='A'`) and returning the first row (`LIMIT 1`). Therefore, the input for Blank C is `""` (a), and Blank D is `' OR 'A'='A' LIMIT 1 -- ` (c). Thus, **C = a**, **D = c**.
