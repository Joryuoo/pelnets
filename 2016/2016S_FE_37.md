# 2016S_FE_37
Which of the following is an appropriate description of Transmission Control Protocol (TCP)?

a) It ensures reliability by retransmission of data segments if any of them is lost.
b) It is an end-to-end protocol but does not have any mechanism for congestion control.
c) It is connectionless and uses a checksum to ensure the integrity of the data.
d) It is connection oriented but cannot operate if packets are received out of order.
?
a) It ensures reliability by retransmission of data segments if any of them is lost.

### Explanation
**Transmission Control Protocol (TCP)** is a core Transport layer protocol characterized by the following features:

- **Reliability via ARQ (Automatic Repeat reQuest)**: TCP ensures that data arrives reliably by tracking sequence numbers and acknowledgments (ACKs). If a sender does not receive an ACK for a transmitted segment before the retransmission timer expires (or if duplicate ACKs indicate packet loss), the sender retransmits the missing segment.
- **Connection-Oriented**: Establishes a virtual connection between endpoints using a three-way handshake (`SYN`, `SYN-ACK`, `ACK`) before transferring data.
- **In-Order Delivery**: Each segment has a 32-bit sequence number. If segments arrive out of order at the receiver, TCP buffers and reassembles them in their original sequence before handing the stream to the application layer.
- **Congestion and Flow Control**: Uses sliding window mechanisms for flow control (preventing receiver buffer overflow) and congestion window algorithms (Slow Start, Congestion Avoidance, Fast Retransmit/Recovery) to mitigate network congestion.

**Analysis of incorrect options:**
- **b)** Incorrect. TCP includes extensive congestion control mechanisms (e.g., Tahoe, Reno, CUBIC).
- **c)** Incorrect. TCP is connection-oriented, not connectionless (UDP is connectionless).
- **d)** Incorrect. TCP easily operates when packets arrive out of order; it reorders them using sequence numbers.
