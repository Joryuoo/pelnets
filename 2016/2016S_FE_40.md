# 2016S_FE_40
When malware that has made a successful intrusion into a PC communicates with a command-and-control server on the Internet, which of the following is a reason for using the TCP port number 80 as the destination port in most cases?

a) As this port is used for browsing websites, there is a high probability that communication is allowed by the firewall.
b) As this port is used for browsing websites through the HTTPS protocol, there is a low probability that this port is detected by an intrusion detection system.
c) As this port is used for name resolution of a domain name, there is a low probability that this port is detected by an intrusion detection system.
d) As this port is used in a DNS zone transfer, there is a high probability that communication is allowed by the firewall.
?
a) As this port is used for browsing websites, there is a high probability that communication is allowed by the firewall.

### Explanation
**Command-and-Control (C&C or C2)** servers are used by attackers to maintain control over infected compromised systems (bots) and issue instructions or exfiltrate stolen data.

- **Port 80** is the well-known TCP port designated for **HTTP (Hypertext Transfer Protocol)**, the foundation for web browsing.
- In enterprise perimeter security architectures, egress traffic is often restricted by firewalls. However, outbound access on port 80 (HTTP) and port 443 (HTTPS) is almost universally allowed (or proxied) to enable employees and internal devices to browse the Internet.
- Malware developers deliberately leverage destination port 80 to disguise malicious C&C communication as standard outbound HTTP traffic, ensuring a very high probability that the outbound packets will be permitted through egress firewall filtering rules.

**Analysis of incorrect options:**
- **b)** HTTPS uses TCP port **443**, not port 80. Port 80 transmits unencrypted HTTP.
- **c)** DNS name resolution operates on port **53** (predominantly UDP, occasionally TCP), not port 80.
- **d)** DNS zone transfers operate on TCP port **53**, not port 80.
