# 2016S_FE_48

Which of the following can be implemented with the functions of HTTPS (HTTP over SSL/TLS)?

a) Blocking of communication aside from TCP port numbers 80 and 443
b) Encryption of communication between a Web server and a browser
c) Restriction of unauthorized access to a Web server through packet filtering in the Network Interface layer
d) Prevention of an attack on a Web server from an SQL injection
?
b) Encryption of communication between a Web server and a browser

### Explanation

**HTTPS (Hypertext Transfer Protocol Secure)** is an extension of HTTP that layers standard HTTP communication over **SSL/TLS (Secure Sockets Layer / Transport Layer Security)** protocols, conventionally using TCP port 443.

#### Core Security Functions of HTTPS:
1. **Confidentiality (Encryption)**: All communication between the Web browser (client) and the Web server is encrypted using symmetric session keys negotiated during the TLS handshake. This prevents eavesdropping and tampering by intermediaries (e.g., on public Wi-Fi networks).
2. **Authentication**: The server provides an X.509 digital certificate signed by a trusted Certificate Authority (CA) to prove its identity to the browser.
3. **Data Integrity**: Uses Message Authentication Codes (MACs) to ensure that the transmitted web traffic cannot be altered or injected into in transit without immediate detection.

Therefore, **encryption of communication between a Web server and a browser** is a fundamental function of HTTPS (**choice b**).

### Option Analysis
- **a)** Blocking traffic based on TCP/UDP port numbers is a function of a **packet-filtering firewall**, not HTTPS.
- **b)** **Correct**. Encrypting HTTP session data between the client and server is the primary purpose of HTTPS.
- **c)** Packet filtering at lower network layers (Network Interface layer / Data Link layer) is handled by network firewalls, switches (e.g., port security, MAC filtering), or network ACLs.
- **d)** HTTPS secures the transport channel, but does not inspect or sanitize application input. If an attacker sends an SQL injection attack over HTTPS, it will simply be encrypted in transit and executed on the vulnerable database backend unless prevented by prepared statements / parameterized queries or a WAF.
