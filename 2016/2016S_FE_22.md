# 2016S_FE_22

![[2016S_FE_AM_Q22_full.png]]

c) 150

?
b) 140

### Explanation

We are given a dual-CPU system where CPU and Resource $R$ are both available at time $t = 0$.
Resource $R$ is shared and must be used **exclusively** (only one task can use $R$ at a time).
The system has two CPUs, so both tasks can execute their CPU stages simultaneously if a CPU is free.

#### Task Workloads:
- **Task A:**
  1. CPU: 10 ms
  2. Resource $R$: 50 ms
  3. CPU: 60 ms
- **Task B:**
  1. CPU: 40 ms
  2. Resource $R$: 50 ms
  3. CPU: 30 ms

---

#### Step-by-Step Execution Timeline:

| Time Interval (ms) | Task A State | Task B State | Notes |
| :--- | :--- | :--- | :--- |
| **0 – 10** | **CPU (10 ms)** | **CPU (10 / 40 ms)** | Both tasks execute CPU phases on separate CPUs. |
| **10 – 40** | **Resource $R$ (30 / 50 ms)** | **CPU (continues 30 ms)** | Task A finishes its first CPU burst at $t=10$ and acquires Resource $R$. Task B continues its CPU burst. |
| **40 – 60** | **Resource $R$ (finishes remaining 20 ms)** | **WAITING for Resource $R$** | At $t=40$, Task B finishes its first CPU burst and requests Resource $R$. Since Task A is holding $R$ until $t=60$, Task B must wait 20 ms. |
| **60 – 110** | **CPU (50 / 60 ms)** | **Resource $R$ (50 ms)** | At $t=60$, Task A releases $R$ and begins its second CPU burst (60 ms). Task B immediately acquires Resource $R$ (needs 50 ms, finishes at $t=110$). |
| **110 – 120** | **CPU (finishes remaining 10 ms)** | **CPU (10 / 30 ms)** | At $t=110$, Task B releases $R$ and starts its second CPU burst on the free CPU. Task A finishes at $t=120$. |
| **120 – 140** | **COMPLETED** | **CPU (finishes remaining 20 ms)** | Task B continues its CPU burst until $t=140$. |

At time **$t = 140$ ms**, both Task A and Task B have fully completed execution.

Therefore, the total time required until completion of both tasks is **140 milliseconds**, which corresponds to **b)**.
