# 2016A_FE_30
Which of the following is an appropriate description of locks?

a) For a resource on which transaction T1 has acquired an exclusive lock, transaction T2 can acquire an exclusive, but not a shared, lock.
b) For a resource on which transaction T1 has acquired an exclusive lock, transaction T2 can acquire either an exclusive or a shared lock.
c) For a resource on which transaction T1 has acquired a shared lock, transaction T2 can acquire a shared, but not an exclusive, lock.
d) For a resource on which transaction T1 has acquired a shared lock, transaction T2 can acquire either a shared or an exclusive lock.
?
c) For a resource on which transaction T1 has acquired a shared lock, transaction T2 can acquire a shared, but not an exclusive, lock.
### Explanation
In Database Management Systems (DBMS), **locking** is a fundamental concurrency control mechanism used to prevent data conflicts and ensure the ACID property of **Isolation**:

#### Types of Locks:
1. **Shared Lock (S-lock / Read Lock):**
   - Acquired by a transaction when reading data without modifying it.
   - **Compatibility:** Multiple transactions can hold shared locks on the exact same resource simultaneously because concurrent reads do not interfere with each other.
   - However, a transaction requesting an **exclusive lock** will be blocked until all existing shared locks on that resource are released.
   - Therefore, if transaction $T_1$ has acquired a shared lock on a resource, transaction $T_2$ **can acquire a shared lock, but cannot acquire an exclusive lock**. This matches **c)**.

2. **Exclusive Lock (X-lock / Write Lock):**
   - Acquired by a transaction when modifying (inserting, updating, or deleting) data.
   - **Exclusivity:** Only one transaction can hold an exclusive lock on a resource at any time.
   - An exclusive lock conflicts with both shared locks and other exclusive locks. While $T_1$ holds an exclusive lock, no other transaction ($T_2$) can acquire *either* a shared lock or an exclusive lock.

#### Lock Compatibility Matrix:
| Currently Held Lock by $T_1$ | Lock Requested by $T_2$: Shared (S) | Lock Requested by $T_2$: Exclusive (X) |
| :--- | :---: | :---: |
| **Shared Lock (S)** | **Compatible (Granted)** | **Incompatible (Blocked)** |
| **Exclusive Lock (X)** | **Incompatible (Blocked)** | **Incompatible (Blocked)** |

**Analysis of incorrect options:**
- **a)** Incorrect. When $T_1$ holds an exclusive lock, $T_2$ cannot acquire *any* lock (neither shared nor exclusive).
- **b)** Incorrect. $T_2$ cannot acquire an exclusive lock or a shared lock while $T_1$ holds an exclusive lock.
- **d)** Incorrect. $T_2$ cannot acquire an exclusive lock while $T_1$ holds a shared lock.
