# 2016S_FE_21

Which of the following is an appropriate explanation for a non-preemptive scheduling method?

a) A task cannot move to a running state until another task in the running state either moves to the waiting state by itself or finishes.
b) Each time a new task becomes the ready state, a comparison is made for all tasks in the ready state from the standpoint of the remaining execution time, and the tasks are executed in an order starting from the shortest execution time.
c) When a task becomes the ready state, a comparison is made between the priority of the task and that of the one in the running state at that time, and the task with the higher priority moves to the running state.
d) When a task in the running state does not move to the waiting state within a predetermined time period, the task is interrupted, and the next task in the waiting queue moves to the running state.
?
a) A task cannot move to a running state until another task in the running state either moves to the waiting state by itself or finishes.

### Explanation

In operating systems, process/task scheduling methods are classified into **preemptive** and **non-preemptive**:

- **Non-preemptive scheduling:** Once a task is allocated the CPU and transitions to the **running state**, it retains control of the CPU until it either:
  1. Voluntarily yields control (moves to the **waiting state**, for instance by requesting an I/O operation or sleeping).
  2. Terminates/completes its execution (**finishes**).
  The OS kernel will never forcibly interrupt a running task to give CPU time to another ready task. Therefore, no other task can move to the running state until the current task yields or finishes. This matches **a)**.

- **Preemptive scheduling:** The operating system can forcibly suspend (preempt) a currently running task and allocate the CPU to another task based on criteria such as priorities or time slices.

**Analysis of incorrect options:**
- **b)** describes **Shortest Remaining Time First (SRTF)** scheduling, which is a preemptive scheduling algorithm where a newly arrived task with a shorter remaining burst time can preempt the currently running task.
- **c)** describes **Priority-based Preemptive** scheduling, where a newly arrived task with higher priority immediately preempts the lower-priority running task.
- **d)** describes **Round-Robin (RR)** scheduling, which is preemptive scheduling based on time-slice expiration.
