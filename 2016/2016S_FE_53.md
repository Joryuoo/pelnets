a) Adapter
### Explanation
The **Adapter** pattern is a structural design pattern (from the Gang of Four) that allows objects with incompatible interfaces to collaborate by converting the interface of a class into another interface that the client expects.

The two diagrams illustrate the two classic implementations of the Adapter pattern:
1. **Object Adapter (Top Diagram)**:
   - Uses object composition.
   - The adapter class (`Object-------`) realizes/implements the `Expected` interface and holds an internal reference (has-a) to `StructClass` (the adaptee).
   - When the client calls `expectedMethod()`, the adapter delegates the call to `structClass.specificMethod()`.
2. **Class Adapter (Bottom Diagram)**:
   - Uses multiple inheritance (or class inheritance plus interface implementation).
   - The adapter class (`ClassStructPattern`) inherits from both `Expected` and `StructClass`.
   - When the client calls `expectedMethod()`, the adapter directly executes `specificMethod()`.

Other options:
- **Factory (b)**: A creational design pattern used to create objects without exposing creation logic to the client.
- **Iterator (c)**: A behavioral design pattern used to sequentially access elements of an aggregate object without exposing its underlying representation.
- **Singleton (d)**: A creational design pattern ensuring a class has only one instance and provides a global access point to it.
