### Explanation

*   **A (Answer: d):** In Test case 1, PC21 to PC30 can successfully ping devices within the local network but fail to ping the Web Server (198.51.100.189). Looking at Table 2, the default gateway for PC21 and PC30 is listed as `192.168.1.11`. However, `192.168.1.11` is the IP address of Switch1, which is a Layer 2 device and cannot route traffic outside the local network. The correct gateway should be Router Fe01, which has the IP address `192.168.1.1`.
*   **B (Answer: h):** In Test case 2, PCs in Section Y (PC31 to PC50) can ping each other but fail to ping Router Fe02 (192.168.3.2) or devices in Section X. According to Table 2, PC31 and PC50 are configured with IP addresses `192.168.2.231` and `192.168.2.250`. Their default gateway is Router Fe02 at `192.168.3.2`. Because the subnet mask is `/24`, the network address for the PCs is `192.168.2.0`, while the router is on `192.168.3.0`. The PCs are configured with the wrong IP addresses and need to be in the `192.168.3.xxx` range.
*   **C (Answer: b):** In Test case 3, pinging the Web Server using its IP address (198.51.100.189) was successful in previous tests (for properly configured PCs), but pinging it by its hostname `web.example.com` fails. This indicates that the PCs are unable to resolve the hostname to an IP address, meaning the DNS server address was not configured on the PCs.
