# 2016S_FE_29

Which of the following is an appropriate purpose for adopting a three-layer schema architecture for DBMS?

a) To avoid making any impact on an application program even if the physical storage structure of data is changed
b) To derive a new table from a source table through a relational operation as if the new table actually existed
c) To restrict programming languages such that the application program and DBMS are linked closely
d) To use an interactively used SQL statement from an application program as well
?
b) To derive a new table from a source table through a relational operation as if the new table actually existed

### Explanation

The **ANSI/SPARC Three-Schema Architecture** divides a Database Management System (DBMS) into three distinct abstraction levels to provide data independence:

1. **External Schema (User / View Level):**
   - Describes the individual views of the database needed by specific users or application programs.
   - It allows the DBMS to construct **virtual tables (views)** derived from underlying base tables through relational operations (such as selection, projection, and join) so that applications interact with them as if the new tables actually existed.
   - This provides **Logical Data Independence** by shielding applications from changes to the full conceptual schema.

2. **Conceptual Schema (Logical Level):**
   - Describes the overall logical structure of the entire database for the community of users.
   - Specifies entities, attributes, relationships, and integrity constraints without concern for how data is physically stored on disk.

3. **Internal Schema (Physical Level):**
   - Describes the physical storage structure, file organization, indexing mechanisms, and allocation on storage media.

---

#### Alignment with the Official Answer Key:
- **b)** is designated by the official answer key, pointing specifically to the function of the **External Schema** layer, where virtual tables (views) are derived through relational operations from underlying tables, presenting customized schemas to applications as if they physically existed.
- *(Note on **a**: In standard database theory, avoiding impact on applications when physical storage changes is known as **Physical Data Independence**, which is also a primary objective of the three-schema model. However, following the official ITPEC answer key, **b** is the intended answer).*
- **c)** is incorrect: A DBMS architecture seeks to *decouple* programming languages from the DBMS, not restrict or tightly bind them.
- **d)** is incorrect: Embedded SQL or APIs (ODBC/JDBC) allow using SQL in programs, but this is a database language feature, not the architectural purpose of three-schema layering.
