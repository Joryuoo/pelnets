# 2016A_FE_45
Which of the following can be used to detect worms by using SHA-256 to calculate a hash value from a subject file, and then cross-checking this against a database of hash values from files containing specimens of known worms?

a) A worm that has the same file size as a worm specimen
b) A worm that is in the same subspecies as a worm specimen
c) A worm with code strings that have the same characteristics as a worm specimen
d) The same worm as a worm specimen
?
d) The same worm as a worm specimen
### Explanation
Cryptographic hash functions like **SHA-256** have key mathematical properties:
1. **Determinism and Uniqueness:** The same exact input file will always produce the identical 256-bit hash digest.
2. **Avalanche Effect:** Altering even a single bit in the file results in an entirely different, unpredictable hash digest.
3. **Preimage and Collision Resistance:** It is computationally infeasible to find two different files that produce the exact same SHA-256 hash.

Because of these properties, comparing a computed SHA-256 hash value directly against a database of known worm specimen hashes will only match if the candidate file is an exact, bit-for-bit duplicate—meaning **the same worm as a worm specimen**.

Why the other options are incorrect:
* **a)** Completely different files can easily have identical file sizes. Hash matching verifies exact content, not file size.
* **b)** Subspecies or variants contain modified instructions, obfuscations, or payloads. Any difference in code changes the SHA-256 hash completely, causing exact hash matching to fail.
* **c)** Worms sharing similar code strings or behavioral characteristics require heuristic analysis, fuzzy hashing (e.g., SSDEEP), or pattern matching (e.g., YARA rules). A standard SHA-256 hash cannot detect similarity if other parts of the binary differ.
