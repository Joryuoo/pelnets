### Explanation

**Statement a) is correct:** The text states, "Either side can send a heartbeat request...". Because the protocol is symmetric and the OpenSSL vulnerability existed in both clients and servers using the library, a malicious server can send a malformed heartbeat request to a vulnerable client and read its memory.

**Statement c) is correct:** The Heartbleed bug involves exploiting a missing bounds check to simply read server memory. It does not crash the system, alter data, or execute code. Because it behaves like a standard heartbeat request returning data, it leaves no trace in typical access logs, making it very difficult to investigate or detect past attacks.

**Why the other options are incorrect:**
- **b)** It is not a flaw in the design of the heartbeat extension itself, but an implementation bug (missing bounds checking) in the OpenSSL software. 
- **d)** The bug is a "buffer over-read" vulnerability. Attackers can only read memory contents, not alter memory to execute arbitrary code or gain root access.
- **e)** Just because the bug was discovered in 2014 does not mean it wasn't secretly exploited beforehand. The bug existed in the OpenSSL codebase for a long time before public discovery.
