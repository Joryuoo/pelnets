# 2016A_FE_47
In software development for small projects, which of the following is an appropriate explanation of test driven development (TDD)?

a) All functionalities are identified at the start of the project. Code and test cases are developed together and functionalities are developed simultaneously.
b) Continuous testing is implemented during the coding process using automated testing. The process eliminates the requirement for system testing
c) Development is done in increments of functionality where test cases are executed and the code is developed to pass the test cases before moving to the next increment.
d) Test cases are executed at the end for each stage of the development process where all code must first pass the test case before proceeding to the next stage.
?
c) Development is done in increments of functionality where test cases are executed and the code is developed to pass the test cases before moving to the next increment.
### Explanation
**Test-Driven Development (TDD)** is an iterative software development practice based on very short development cycles:

1. **Red (Write a test):** For a tiny increment of functionality, an automated unit test is written *before* any implementation code. The test is run and must fail.
2. **Green (Write code):** The developer writes only the minimal amount of code required to make the test pass.
3. **Refactor:** The newly written code is cleaned up and refactored for clarity, maintainability, and design without breaking any existing tests.
4. **Repeat:** The developer proceeds to the next small increment of functionality.

Why the other options are incorrect:
* **a)** TDD is an agile practice where requirements and features are built iteratively. Upfront complete specification and simultaneous implementation of all functionalities contradict agile and TDD principles.
* **b)** Automated unit testing in TDD focuses primarily on individual units and components. It does **not** eliminate the requirement for system testing, performance testing, security testing, or end-to-end acceptance testing.
* **d)** Executing test cases only at the end of each stage describes traditional sequential/Waterfall testing, which is the opposite of the test-first approach of TDD.
