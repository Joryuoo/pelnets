# 2026S_FE-A_19

Q19. Which of the following is an appropriate description of the mapping between a relational model and relational database in implementation?

a) A domain is mapped to a character type or a character string type.
b) A relation is mapped to a table.
c) Attributes and columns are ordered from left to right.
d) Neither tuples nor rows have duplicates.
?
b) A relation is mapped to a table.

### Explanation

In database systems, there is a direct mapping between the theoretical concepts of the **relational model** (formulated by E.F. Codd) and the physical structures of a **relational database implementation** (like an RDBMS such as MySQL, Oracle, etc.). 

The mapping works as follows:

| Relational Model Concept | Relational Database Concept |
|---|---|
| **Relation** | **Table** |
| Tuple | Row (or Record) |
| Attribute | Column (or Field) |
| Domain | Data type |

Let's evaluate the choices:
*   **a)** A domain maps to *any* appropriate data type (integer, date, boolean), not just character types.
*   **b)** A **relation** in the mathematical model is physically implemented as a **table**. This is the correct mapping.
*   **c)** In the pure relational model, attributes are an unordered set. While RDBMS implementations usually order columns, it is not an appropriate description of the mapping itself.
*   **d)** In the mathematical relational model, relations are sets of tuples, meaning there are no duplicates. However, in physical implementations (SQL tables), rows *can* have duplicates unless constrained by a primary key or unique constraint.

Therefore, the correct mapping description is that a relation is mapped to a table.
