### Explanation
The SQL authentication template is:
```sql
SELECT * FROM users
WHERE username = '<input_username>' 
  AND password = '<hashed_input_password>'
```

Let's evaluate the payload injections:

1. **Blank A:** `<input_username> = admin' --`
   The injected query becomes:
   ```sql
   SELECT * FROM users
   WHERE username = 'admin' --' 
     AND password = '<hashed_input_password>'
   ```
   The `--` sequence signifies the start of a SQL comment. The database engine ignores everything following it. The query executed is effectively:
   `SELECT * FROM users WHERE username = 'admin'`
   Since the `admin` user exists, this query returns a record, causing the authentication check to pass without a valid password. Thus, the bypass is a **Success**.

2. **Blank B:** `<input_username> = admin' AND '1'='2' --`
   The injected query becomes:
   ```sql
   SELECT * FROM users
   WHERE username = 'admin' AND '1'='2' --' 
     AND password = '<hashed_input_password>'
   ```
   The query executed is effectively:
   `SELECT * FROM users WHERE username = 'admin' AND '1'='2'`
   Although the comment drops the password check, the injected logical condition `'1'='2'` is always false. Therefore, the query returns no records, and the authentication bypass will **Fail**.

The correct combination is **c**.
